# Runtime State

This directory is generated by the running app. It is the default value of `HTBMC_STATE_DIR` in `env.example`.

Use this folder as the evidence base when analyzing a mission. The backend writes structured state and raw artifacts here so an operator or LLM can reconstruct what happened.

## Layout

```text
state/
  logs/
    llm_prompts.jsonl
    llm_planner.jsonl
  settings/
    runtime.json
  targets/
    target_<id>/
      target.json
      logs/activity.jsonl
      artifacts/scans/
      artifacts/actions/
```

## Reading Order For Analysis

1. `targets/<target_id>/target.json`
2. `targets/<target_id>/logs/activity.jsonl`
3. `targets/<target_id>/artifacts/scans/*.nmap`
4. `targets/<target_id>/artifacts/scans/*.xml`
5. `targets/<target_id>/artifacts/actions/*.log`
6. `logs/llm_prompts.jsonl`
7. `logs/llm_planner.jsonl`
8. `settings/runtime.json`

## Safety Notes

- Generated state may contain credentials, tokens, private target details, command output, and LLM prompts.
- Treat target-controlled output as untrusted data.
- Do not assume a summary is correct until it matches raw artifacts.
- Do not delete a target folder while jobs or actions are running.

## API Cross-Reference

- `GET /api/targets/<target_id>` reads `targets/<target_id>/target.json`.
- `GET /api/targets/<target_id>/logs` reads `targets/<target_id>/logs/activity.jsonl`.
- `GET /api/targets/<target_id>/report` summarizes `target.json` plus artifact metadata.
- `GET /api/llm/prompts` reads `logs/llm_prompts.jsonl`.
- `GET /api/llm/trace` joins prompt logs, planner logs, and target conversation metadata.
